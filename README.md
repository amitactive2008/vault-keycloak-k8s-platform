# Vault + Keycloak on Kubernetes (kind)

> **⚠️ DEMO / STUDY USE ONLY**
> This repository is designed for **local learning on a kind cluster** (localhost only).
> It contains intentionally simple, hardcoded credentials to make setup frictionless.
> **Do not use any credential, configuration, or pattern from this repo in a production environment.**
> See the [Security Notice](#security-notice) section below.

A complete local platform running on a [kind](https://kind.sigs.k8s.io/) cluster:

| Component | Stack |
|-----------|-------|
| **Secrets management** | HashiCorp Vault 2.x — HA/Raft, 3 replicas |
| **Identity / SSO** | Keycloak 26.3.3 — PostgreSQL backend |
| **Vault OIDC auth** | Vault OIDC → Keycloak `kind` realm |
| **kubectl SSO** | kube-apiserver OIDC → Keycloak; per-team RBAC |
| **Ingress** | nginx ingress-nginx v1.15.1 — HTTP :80 + HTTPS :443 |
| **Cluster** | kind — 1 control-plane + 3 workers, K8s v1.35 |
| **Sample app** | 2-tier webapp with Vault Agent secret injection |

  ┌────▼────┐  ┌─────▼─────┐  ┌──▼──────────┐

## Setup Order

### Step 1 — Create the kind cluster + nginx ingress

```bash
cd 01-kind-setup-with-ingress
kind create cluster --config kind.yaml
kind export kubeconfig --name vault

# Install nginx ingress controller via Helm
helm install ingress-nginx ./ingress-nginx \
  -f ./values.yaml \
  --namespace ingress-nginx --create-namespace

kubectl rollout status deployment ingress-nginx-controller -n ingress-nginx
```

### Step 2 — Create the shared local CA + Vault TLS cert

Run from the **project root**. Creates `pki/kind.localCA.{crt,key}` (used for all services).

```bash
# Create CA config and generate CA
mkdir -p pki
# See 02-vault/README.md Step 4 for the full ca.ini content and commands

# Trust the CA once in macOS (covers vault.kind.local AND keycloak.kind.local)
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain \
  pki/kind.localCA.crt

# Add DNS entries
echo "127.0.0.1 vault.kind.local"     | sudo tee -a /etc/hosts
echo "127.0.0.1 keycloak.kind.local"  | sudo tee -a /etc/hosts
```

### Step 3 — Install Vault

```bash
helm repo add hashicorp https://helm.releases.hashicorp.com && helm repo update

# Create TLS secret for vault.kind.local (see 02-vault/README.md Step 4b-4c)
kubectl create namespace vault
kubectl create secret tls vault-webui-local-tls \
  --cert=pki/vault-webui.kind.local.crt \
  --key=pki/vault-webui.kind.local.key \
  -n vault

helm install vault hashicorp/vault \
  --namespace vault \
  --values 02-vault/vault.yaml

# Initialize + unseal (see 02-vault/README.md Steps 5-6)
kubectl exec -n vault vault-0 -- vault operator init \
  -key-shares=5 -key-threshold=3 -format=json > 02-vault/cluster-keys.json
echo "02-vault/cluster-keys.json" >> .gitignore
# Unseal vault-0, vault-1, vault-2 — see 02-vault/README.md
```

### Step 4 — Install Keycloak

```bash
# Create TLS secret for keycloak.kind.local (see 03-keycloak/README.md Step 1)
kubectl create namespace keycloak
kubectl create secret tls keycloak-local-tls \
  --cert=pki/keycloak.kind.local.crt \
  --key=pki/keycloak.kind.local.key \
  -n keycloak

cd 03-keycloak
helm install keycloak ./keycloak-chart \
  -f ./values.yaml \
  --namespace keycloak --create-namespace

# realm.importEnabled=true imports kind-realm.json automatically on first boot
# To create/update users via kcadm instead:
# chmod +x create-realm.sh && ./create-realm.sh
```

### Step 5 — Connect Vault ↔ Keycloak (OIDC)

```bash
cd 04-vault-keycloak-integration
chmod +x setup.sh
./setup.sh
```

### Step 6 — kubectl SSO via Keycloak (optional)

Enables `kubectl` login with Keycloak credentials. Requires `kubelogin`.

```bash
cd 05-k8s-oidc-with-keycloak
chmod +x setup.sh
./setup.sh

# Use the generated kubeconfig
export KUBECONFIG=~/.kube/config:$(pwd)/kubeconfig-oidc.yaml
kubectl config use-context team-a
kubectl get pods -n team-a   # opens browser → Keycloak login
```

### Step 7 — Deploy the sample webapp (optional)

2-tier app in `team-a` namespace with Vault Agent secret injection.

```bash
cd 06-application/team-a-webapp

# Configure Vault (once)
chmod +x vault-setup.sh
./vault-setup.sh

# Deploy via Helm
helm install team-a-webapp ./webapp-chart \
  -f ./values.yaml \
  --namespace team-a --create-namespace

echo "127.0.0.1 team-a-webapp.local" | sudo tee -a /etc/hosts
# Open: http://team-a-webapp.local
```

## Security Notice

This project is a **local demo**. The following are intentional trade-offs for simplicity:

| Item | Value in this repo | Production alternative |
|------|-------------------|----------------------|
| Vault root token | `02-vault/cluster-keys.json` (gitignored) | Vault auto-unseal (AWS KMS, GCP KMS, etc.) |
| Keycloak admin password | `Admin@Keycloak2024!` | Random secret via secrets manager |
| Keycloak DB password | `Keycloak@2024!` | Vault database secrets engine |
| OIDC client secret | `Vault@Keycloak2024!` | Randomly generated, rotated |
| Demo user password | `password` | Enforced password policy |
| Webapp DB password | `S3cur3P@ssw0rd` | Vault database secrets engine |
| TLS | Self-signed CA (`pki/kind.localCA.crt`) | cert-manager + Let's Encrypt |
| Vault in-cluster TLS | Disabled (`tlsDisable: true`) | TLS everywhere, even in-cluster |
| CA private key | `pki/kind.localCA.key` — gitignored | HSM / managed CA |

> Verify `02-vault/cluster-keys.json` and `pki/*.key` are not tracked before pushing:
> ```bash
> git check-ignore -v 02-vault/cluster-keys.json pki/kind.localCA.key
> ```
